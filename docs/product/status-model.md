# Public product status model

Novera Protocol uses a controlled status vocabulary across its website and public repositories. Every capability claim should resolve to one of these states.

| State | Meaning |
|---|---|
| **MVP mock** | An illustrative workflow or interface using synthetic data |
| **MVP** | Implemented within the stated pre-production scope |
| **Planned** | A roadmap intention that is not currently available |
| **Under evaluation** | An open technical, commercial, security, legal, or product decision |
| **Conditional** | Dependent on an external provider, approval, requirement, or validated use case |
| **Not in MVP** | Explicitly excluded from the current delivery scope |

## Claim rules

1. A prototype, schema, diagram, or interface proposal is not production availability.
2. Compatibility, evaluation, or architectural alignment is not an integration, endorsement, or partnership.
3. A recorded assertion is not a legal, regulatory, financial, or identity determination.
4. A network candidate is not a selected production blockchain.
5. A planned capability has no delivery date unless a dated, approved public source states one.
6. Metrics, customers, users, transactions, TVL, uptime, and partner activity must not be published without verifiable evidence and explicit authorization.
7. NOVA and NovaStable are not part of the current MVP. No token or stable-value asset has been issued, offered, reserved, or deployed.

## Current governing position

- Novera is **EVM-first and chain-agnostic**.
- No production blockchain is selected.
- Base is a leading candidate under evaluation only.
- Hedera is an optional future adapter.
- Chainlink CRE, CCIP, and Proof of Reserve are conditional future integrations.
- NovaID and NovaDeed are MVP mock concepts using synthetic data.
- NovaRegistry is an MVP synthetic asset-record model.

The canonical public summary is [noveraprotocol.org/status](https://noveraprotocol.org/status).
